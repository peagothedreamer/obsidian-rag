## 2. 关键发现：RRF 候选池截断

### 2.1 案例 p03

诊断结果：

```
纯向量 top-20       → 金标不在
BM25 top-20        → 金标排第 17
RRF 融合后         → 金标掉到第 30 / 35
精排只看前 20 条   → 金标被截掉
精排看全部 35 条   → 金标排第 1，分数 0.9945
```

### 2.2 根因

RRF 分数是 `Σ 1/(60 + rank)`。只在一路出现、排第 17 的条目得分约 0.013；两路各排第 10 的条目得分约 0.029。RRF 奖励「两路共识」，惩罚单路命中，所以金标被压到 20 名之外。

**RRF 是排序方法，不应被当成候选生成器。** 精排应当看到两路召回的全部候选。

### 2.3 修复

`rag/search.py`：精排候选池改为两路召回的完整并集（最多 `2 × recall_k`）。

```python
def search(
    self,
    query: str,
    top_k: int = config.TOP_K,
    no_rerank: bool = False,
    recall_k: int | None = None,
    rerank_n: int | None = None,
) -> list[RetrievedChunk]:
    recall_k = recall_k or config.RECALL_K
    rerank_n = rerank_n or recall_k * 2
    ...
    candidates = fused[:top_k] if no_rerank else fused[:rerank_n]
```

### 2.4 实测耗时（单次查询）

| 精排候选数          | 耗时                         |
| ------------------- | ---------------------------- |
| 20                  | 4.55 s                       |
| 35                  | 7.43 s                       |
| 35 + max_length=384 | 7.29 s（收益可忽略，不采用） |

### 2.5 修复后结果

`reports/eval_paraphrase_v2.md`：

| 配置                        | Recall@5 | MRR@10 |
| --------------------------- | -------- | ------ |
| hybrid+rerank               | 1.000    | 0.763  |
| 引用命中率（hybrid+rerank） | 1.000    | -      |

- p03 修复后排第 1（MRR = 1.0），验证了候选池截断的根因判断。
- 12 题全部进入 top-5；MRR 0.763，未排第一的 4 题：p01（第 4）、p02（第 2）、p07（第 5）、p10（第 5）。

- 问题性质从「召不回」变成「排序不够靠前」，下一阶段应针对排序而非召回。

## 3. 待验证的检索改进

- **查询指令前缀**：bge-m3 通常不需要 instruction，但可 A/B 测试 `为这个句子生成表示以用于检索相关文章：` 是否提升改写题向量召回。
- **embedding 模型**：对比 `bge-large-zh-v1.5`、`gte-multilingual-base`；需要重建索引，成本较高。
- **chunk 前缀去重**：当前前缀出现 `1.13-体效应与大信号模型 > 1.13 体效应与大信号模型 > 体效应` 的重复，可能稀释正文语义。
- **向量召回诊断**：p03 的纯向量 top-20 完全没命中，应统计改写集的 vector Recall@20，区分「召回不到」与「排得太后」。
- **精排耗时**：候选并集预热后约 7.4 秒/题，评测中实测约 11.3 秒/题；max_length 缩短无收益。后续可试 ONNX、量化或更小模型，但暂不作为主线。
- **精排与 MRR 的权衡**：基础集上精排 Recall 升但 MRR 略降，说明 reranker 的排序标准与 gold note 不完全一致，可在报告中如实说明，不强行解释。
